Design Paradigm

Layered REST API + Feature-Slice SPA. The backend is a strict top-down layered system. The frontend is organized into independent vertical feature slices sharing a thin common library. All cross-boundary communication is REST — the two halves are separately deployable from day one.

Dependency arrows are strictly top-down. Services may call sibling services (e.g. leaveRequest calls audit and notification), but never routes or controllers.

Frontend feature slices

features/auth/ features/leaves/ features/employees/ features/departments/ features/calendar/ features/reports/ features/audit/ features/profile/

Each slice owns its own components, hooks, and query logic. All slices share lib/apiClient, lib/queryClient, and components/. No slice imports from another slice — shared logic goes to lib/ instead.

Architecture Decisions — All 16

The durable contract between independent builders. Breaking any of these creates integration risk.

AD-1
RBAC enforced server-side on every protected route
Binds: All API routes, NFR-SEC-1
Every protected route passes through middleware/auth (JWT validation) then middleware/rbac (role check). Frontend guards are UI convenience only.
AD-2
leave_balances table is the authoritative balance store
Binds: FR-BAL, FR-REQ, FR-APPR
All balance reads and writes go through services/leaveBalance. No code may calculate a balance by summing approved leave_requests.
AD-3
All list endpoints are server-side paginated
Binds: FR-SRCH, FR-REQ, FR-APPR, FR-RPT, FR-AUDIT, FR-EMP
Every list endpoint accepts ?page=&limit= (default 20) and returns { data, meta: { page, limit, total } }. No unbounded array responses.
AD-4
Balance mutation, status change, overlap check, and cancel restore are all transaction-scoped
Binds: FR-BAL-4, FR-APPR-4/5, FR-REQ-2/4
approve(), reject(), and cancel() use prisma.$transaction. Overlap SELECT in submit() runs inside the same transaction (prevents TOCTOU). cancel() restores the stored duration_days — never recalculates.
AD-5
Access token in React memory only; refresh token in httpOnly cookie
Binds: FR-AUTH-4, NFR-SEC-3
Access token lives in AuthContext state — never localStorage or a JS-readable cookie. Refresh token is set HttpOnly; SameSite=Strict by the API.
AD-6
File I/O goes through a storage abstraction
Binds: FR-REQ-5, FR-APPR-6, NFR-SEC-2
utils/storage.ts is the only file that touches disk or the R2 SDK. Exposes save(buffer, filename) and getSignedUrl(filename). Active backend selected by STORAGE_PROVIDER env var (local | r2).
AD-7
Email notifications are fire-and-forget
Binds: FR-NOTIF-1, FR-NOTIF-2, FR-NOTIF-3
Services call utils/email.send() after the DB transaction commits. email.send() catches its own errors and never re-throws. Email failure does not affect the HTTP response.
AD-8
Audit log is append-only
Binds: FR-AUDIT-3
services/audit exposes only append(entry). No update or delete method exists. Application code may never issue UPDATE or DELETE on audit_logs.
AD-9
Working-day calculation is server-side
Binds: FR-REQ-2, FR-HOL-2
utils/workingDays.ts is the single implementation. The frontend renders the server-returned duration_days — it does not recalculate.
AD-10
Unified API response envelope
Binds: All API routes
Every response body is { success: boolean, data?: T, error?: string, meta?: { page, limit, total } }. HTTP status codes carry semantics. No custom numeric error codes.
AD-11 [ASSUMPTION: monorepo]
Frontend and backend are sibling directories; no shared runtime module
Binds: All, NFR-DEPL-1
frontend/ and backend/ are top-level siblings. Nothing in frontend/ imports a path from backend/ at runtime.
AD-12
Annual balance reset is a scheduled job, not an HTTP endpoint
Binds: FR-BAL-3
Implemented as a node-cron job or DB-level scheduled function. No POST /admin/reset-balances route.
AD-13 · ADOPTED
PDF export uses @cantoo/pdf-lib; Puppeteer excluded from v1
Binds: FR-RPT-4
All PDF generation through utils/pdf.ts using @cantoo/pdf-lib (active fork of the abandoned pdf-lib). Avoids a 300 MB headless browser dependency.
AD-14
Notification recipient contract is fixed per event type
Binds: FR-NOTIF-1, FR-NOTIF-2, FR-NOTIF-3
SUBMITTED → reporting manager. APPROVED → submitting employee. REJECTED → submitting employee. ADMIN_CANCELLED → submitting employee.
AD-15
leave_balances rows provisioned eagerly, never lazily
Binds: FR-BAL, AD-2
services/user.create() inserts one balance row per active leave type. New leave types trigger a migration/admin step to backfill existing users. Lazy on-read creation is prohibited.
AD-16
Every notifiable event writes an in-app row AND sends email
Binds: FR-NOTIF-1 – FR-NOTIF-4, AD-7
services/notification.trigger(event, userId) always writes a notifications row and always calls utils/email.send(). Neither path is optional. Email failure (AD-7) does not prevent the DB row.

Security Model

🔐
RBAC is always server-side (AD-1). Every protected API route validates the JWT and asserts the required role. The frontend role-checks are UI sugar — bypassing them by calling the API directly must still fail.
⚠️
Token storage (AD-5). Access tokens live in AuthContext React state only. Refresh tokens are set by the API as HttpOnly; SameSite=Strict cookies. XSS cannot reach either.

File upload constraints (NFR-SEC-2)

Enforced by middleware/upload.ts (Multer): allowed MIME types application/pdf, image/jpeg, image/png; maximum 5 MB. Rejected uploads return 400 before reaching the controller.

Key operational notes

  • Schema managed exclusively by Prisma migrations — prisma migrate deploy on each release (NFR-DEPL-2).
  • Seed script (prisma/seed.ts) is idempotent — safe to re-run; creates demo accounts if missing.
  • Balance reset job (jobs/resetBalances.ts) runs on Jan 1 via node-cron. No HTTP exposure (AD-12).
  • Prisma 7 requires explicit prisma.config.ts for datasource URL + driver adapter — env vars are not auto-loaded.
  • All secrets via environment variables; .env.example documents required keys (NFR-SEC-4).

Deferred Decisions

Intentionally out of scope for this spine. Each has a clear condition under which to revisit.

Production hosting provider — Vercel vs Netlify vs Railway vs Render vs Supabase. Pick at deployment time; the spine is provider-agnostic.
React form library — React Hook Form vs plain controlled components. Per-feature choice; no cross-feature consistency requirement.
In-app notification delivery — polling interval or WebSocket upgrade. Not load-bearing for v1 leave lifecycle; decide when building the notification badge.
Shared type package — formal shared/ npm workspace vs manually sync'd lib/types.ts. Upgrade if type drift becomes a problem.
Rate limiting on auth endpoints — brute-force protection on POST /auth/login. Add before any public non-portfolio exposure.
Leave carry-forward — explicitly out of scope v1 (PRD § 7). v2 decision.
