- (decision) AD-1 RBAC server-side enforcement. Binds: all protected routes. Prevents: UI-only RBAC bypass (NFR-SEC-1). Rule: every protected API route validates JWT AND checks role server-side via rbac middleware; frontend enforcement is UI convenience only.
- (decision) AD-2 Leave balance is a dedicated table. Binds: FR-BAL, FR-REQ, FR-APPR. Prevents: balance calculated ad hoc from leave_requests history (divergent totals). Rule: leave_balances table is the single source of truth; all reads and writes go through services/leaveBalance.
- (decision) AD-3 Server-side pagination on all list endpoints. Binds: FR-SRCH, FR-REQ, FR-APPR, FR-RPT. Prevents: unbounded DB queries and inconsistent pagination contracts. Rule: every list endpoint accepts page + limit params and returns { data, meta: { page, limit, total } }; default limit 20.
- (decision) AD-4 Balance deduction and request status update are a single Prisma transaction. Binds: FR-BAL-4, FR-APPR-4, FR-APPR-5. Prevents: approved leave with no deduction, or deduction with no status update. Rule: services/leaveRequest approve/reject/cancel methods use prisma.$transaction; no partial writes allowed.
- (decision) AD-5 Access token in client memory only; refresh token in httpOnly cookie. Binds: FR-AUTH-4, NFR-SEC-3. Prevents: XSS token theft from localStorage. Rule: frontend stores access token in AuthContext React state only (never localStorage/sessionStorage); refresh token is set by the API as httpOnly, SameSite=Strict cookie.
- (decision) AD-6 File storage behind an abstraction layer. Binds: FR-REQ-5, FR-APPR-6. Prevents: dev/prod code divergence in upload and retrieval paths. Rule: all file I/O goes through utils/storage.ts which exposes save(buffer, filename) and getUrl(filename); implementation swaps local disk vs Cloudflare R2 based on STORAGE_PROVIDER env var.
- (decision) AD-7 Email notifications are fire-and-forget. Binds: FR-NOTIF-1 through FR-NOTIF-3. Prevents: email failure rolling back a leave approval/rejection. Rule: services call utils/email.send() after the DB transaction commits; email errors are logged but do not throw to the caller and do not affect the HTTP response.
- (decision) AD-8 Audit log is append-only; no update or delete. Binds: FR-AUDIT-3. Prevents: audit trail tampering or accidental deletion. Rule: services/audit exposes only an append(entry) method; no update/delete methods exist; DB-level: no application code ever issues UPDATE/DELETE on audit_logs.
- (decision) AD-9 Working-day calculation is server-side. Binds: FR-REQ-2, FR-HOL-2. Prevents: client/server disagreement on leave duration. Rule: utils/workingDays.ts is the single implementation; it is called by services/leaveRequest at submission and approval time; the frontend displays the server-returned duration, never recalculates.
- (decision) AD-10 Unified API response envelope. Binds: all API routes. Prevents: inconsistent success/error shapes across the frontend API client. Rule: every API response is { success: boolean, data?: T, error?: string, meta?: { page, limit, total } }; HTTP status codes carry semantics; no custom numeric error codes.
- (decision) AD-11 Frontend and backend are separate deployment units in a monorepo. Binds: all. Prevents: direct frontend imports of backend modules. Rule: frontend/ and backend/ are sibling directories; all cross-boundary communication is via REST API; no shared runtime module between them. - (decision) AD-12 Balance reset is a server-side scheduled job, never an HTTP endpoint. Binds: FR-BAL-3. Prevents: accidental or unauthorized reset via HTTP call. Rule: implement as a node-cron job inside the backend process (or a Supabase/Railway scheduled function); do not expose a reset-balances API route.
- (decision) AD-13 PDF generation uses pdf-lib, not Puppeteer. [ADOPTED from PRD addendum recommendation]. Binds: FR-RPT-4. Prevents: 300MB headless browser dependency on the backend. Rule: use pdf-lib for all PDF export; migrate to Puppeteer only if layout complexity demands it (v2).

Backend layers (strict top-down dependency): routes → controllers → services → Prisma/DB; services may call sibling services (e.g. leaveRequest calls audit, notification) but never routes or controllers. Frontend: features/ slices are the primary unit; shared code lives in lib/ and components/.

- (decision) AD-14 Notification recipient contract per event. Binds: FR-NOTIF-1 through FR-NOTIF-3. Prevents: builder disagreement on who receives each notification. Rule: SUBMITTED → employee's reporting manager; APPROVED → submitting employee; REJECTED → submitting employee; ADMIN_CANCELLED → submitting employee.
- (decision) AD-15 leave_balances rows are provisioned eagerly, never lazily. Binds: AD-2, FR-BAL. Prevents: lazy creation silently crediting 0 instead of default_quota, and missing rows for users created before a leave type was added. Rule: balance rows created in services/user.create() (one row per active leave type); also created in migration/seed when a new leave type is added. Lazy on-read creation is prohibited.
- (decision) AD-16 Every notifiable event writes both an in-app notifications row AND calls email.send(). Binds: FR-NOTIF-1 through FR-NOTIF-4, AD-7. Prevents: one builder using only email, another only the notifications table. Rule: services/notification.trigger(event, userId) always writes a notifications row AND calls utils/email.send(); neither path is optional.
