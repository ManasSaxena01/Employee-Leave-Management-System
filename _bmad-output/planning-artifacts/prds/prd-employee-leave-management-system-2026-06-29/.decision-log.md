# Decision Log — Employee Leave Management System PRD

## Session: 2026-06-29

### DL-001 — Leave type management approach
**Decision:** Admin can add/rename leave types via a simple CRUD table; no rule engine.
**Rationale:** Portfolio scope — rule engines add complexity without adding demonstrable value. Simple flag (document required?) delivers the impression with minimal complexity.
**Status:** Captured in PRD (FR-LT)

### DL-002 — Leave balance allocation model
**Decision:** Fixed annual quota per leave type, same for all employees by default. Admin can override per employee. No accrual or pro-ration logic.
**Rationale:** Avoids accrual complexity entirely. Admin override covers edge cases adequately.
**Status:** Captured in PRD (FR-BAL)

### DL-003 — Carry-forward
**Decision:** No carry-forward in v1. Balances reset to quota on January 1st.
**Rationale:** Explicit out-of-scope decision by user. Noted as v2 feature.
**Status:** Captured in PRD (FR-BAL-3, Out of Scope)

### DL-004 — Approval workflow
**Decision:** Single-level approval only. Manager approves direct reports; admin can approve any request. No escalation chains.
**Rationale:** Sufficient for portfolio demonstration. Escalation adds complexity without proportional value.
**Status:** Captured in PRD (FR-APPR)

### DL-005 — Overlapping leave handling
**Decision:** Warn only; do not block submission.
**Rationale:** User's call — blocking is a UX fight not worth taking in v1. Warning banner is sufficient signal.
**Status:** Captured in PRD (FR-REQ-4)

### DL-006 — Document upload requirement
**Decision:** Document requirement is a per-leave-type flag (checkbox). Sick = required by default, Annual = not required.
**Rationale:** Simple flag delivers a portfolio-impressive feature with minimal implementation complexity.
**Status:** Captured in PRD (FR-LT-4, FR-REQ-5)

### DL-007 — Stakes calibration
**Decision:** Portfolio/learning project.
**Impact:** PRD rigor calibrated accordingly — lean, complete, no enterprise compliance sections.

### DL-008 — Tech stack
**Decision:** Captured in addendum.md (not in PRD body — PRD stays capability-focused).
**Status:** See addendum.md

### DL-009 — Demo seed data
**Decision:** Three seeded accounts (admin/manager/employee) with known passwords. Seed script idempotent.
**Rationale:** Zero-friction demo for interviewers is a stated success criterion.
**Status:** Captured in PRD (FR-SEED)

**Decision:** Insufficient balance → warn + allow submission. Manager decides on approval.
**Rationale:** User confirmed. Consistent with overlap handling (warn, don't block).
**Status:** [ASSUMPTION] tag removed from PRD.
